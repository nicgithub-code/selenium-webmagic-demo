# 二、零前端基础速成（爬虫只要这 4 样东西）

> 你不需要去学 HTML/CSS/JS 全套。写爬虫，只要能"看懂网页长啥样、能精准点到想要的内容"就够了。
> 下面 4 块是**最小必要知识**，配合浏览器的开发者工具（F12）就能干活。

---

## 1. 标签、属性、层级（看懂网页的"零件"）

网页是嵌套的"盒子套盒子"。爬虫眼里，它长这样：

```html
<div class="book-card" data-id="b1">          <!-- 一个大盒子，class 叫 book-card -->
  <h3 class="title"><a href="/book-detail?id=b1">Java 爬虫入门</a></h3>  <!-- 标题，里面有个链接 -->
  <p class="price">价格：¥59.80</p>            <!-- 一段文字 -->
  <ul class="tags"><li>Java</li><li>爬虫</li></ul>  <!-- 一个列表，多个小项 -->
</div>
```

- **标签**：`<div>` `<h3>` `<p>` `<a>` `<ul>` `<li>`… 就像"零件类型"
- **属性**：`class="book-card"`、`href="/book-detail?id=b1"`、`data-id="b1"`… 是零件身上的"标签/地址"
- **层级**：`div > h3 > a` 表示"a 在 h3 里面，h3 在 div 里面"，这是后面写选择器的依据

---

## 2. id 与 class（用来"点名"）

- `id`：全页面唯一，相当于身份证号。定位精准，但一个页面里同名 id 只有一个。
- `class`：可以重复，相当于"分组"。比如 6 本书都是 `class="book-card"`，一句选择器就能全选出来。

> 爬虫 90% 的挑选，都是在用 `class` 把"同一类东西"一次性抓出来。

---

## 3. CSS 选择器（WebMagic `.css()` / Selenium `By.cssSelector` 都用它）

选择器就是"按特征点名"的语法。记住下面这几条就够用：

| 想要 | 选择器写法 | 含义 |
|---|---|---|
| 所有 `div` | `div` | 标签名 |
| class 为 `book-card` 的元素 | `.book-card` | 前面加 `.` |
| id 为 `app` 的元素 | `#app` | 前面加 `#` |
| `div` 里所有的 `a` | `div a` | 空格 = 后代 |
| 既是 `div` 又是 `book-card` | `div.book-card` | 连写 |
| `h3` 且 class 是 `title` 里的 `a` | `h3.title a` | 组合 |
| `a` 的链接地址 | `a` 的 `href` 属性 | 用属性取，见下 |

取"属性"还是"文字"：
- WebMagic：`card.css("h3.title a", "href").get()` —— 第二个参数传属性名 `href`
- Selenium：`element.getAttribute("href")`
- 取标签里的**文字**：WebMagic 用 `.xpath(".../text()")`，Selenium 用 `element.getText()`

> 本工程的 `BookListPageProcessor.java` 每一行选择器都有注释，建议直接对照看。

---

## 4. XPath（更强大的"路径语言"，WebMagic 默认支持）

XPath 和 CSS 选的东西差不多，但更擅长"按文字内容过滤""按层级精确剪枝"。本工程里我们用 XPath 从一个"卡片"里抠字段：

```java
// 在"这张卡片"范围内，找 <h3 class="title"> 里面的 <a> 的文字
card.xpath("h3[@class='title']/a/text()").get();

// 找 <p class="author"> 的文字，并用正则去掉"作者："前缀
card.xpath("p[@class='author']/text()").replace("^作者[:：]\\s*", "").get();

// 找所有 <li> 的文字（标签可能有多个）
card.xpath("ul[@class='tags']/li/text()").all();
```

`/` 表示下一层，`@class` 表示属性，`text()` 表示文字内容，`.all()` 一次取多个。

---

## 5. CSS 与 XPath 怎么选（对照速查）

> 常见困惑：`BookListPageProcessor.java` 第 63–68 行用 XPath，第 46/54/79 行却用 CSS，到底该学哪个？

### 先解开误会：不是二选一，是场景不同

- **demo 自己就混用了两种**。第 46、54、79 行是 `.css()`（第 79 行还证明 CSS 一样能取链接 `.links().all()`），只有抠字段那几行用 XPath。作者在第 60 行注释里写了「XPath 更灵活，能挑文本、属性、按文本内容过滤」——这是**刻意让你两种都见一下**，不是"必须用 XPath"。
- **在浏览器 DevTools Console 里回答时给的是 CSS**，因为浏览器原生只有 `document.querySelectorAll` / `$$()`，写 CSS 最顺手；XPath 得用啰嗦的 `document.evaluate(...)`。
- 所以"CSS 看起来简便"有个错觉：如果例子只做到"选中卡片"，当然短；完整做到取文字、去前缀、取多个 li，两种写法长度差不多。

### 一句话本质

HTML 是一棵**标签树**（`div` 套 `h3` 套 `a`）。CSS 和 XPath 都是**"在树里描述地址"的写法**，作用一样、能互相翻译：

- **CSS** ≈ 按元素身上贴的"名牌"找人：`div.book-card h3.title a`
- **XPath** ≈ 写文件路径：`//div[@class='book-card']/h3[@class='title']/a`

### 逐行对照（对着 `pages/books-list.html`）

| 要找的东西 | CSS | XPath（在 `card` 上调用，写相对路径） |
|---|---|---|
| 所有书卡 `<div class="book-card">` | `div.book-card` | `//div[@class='book-card']` |
| 书名链接 `<h3 class="title"><a>` | `h3.title a` | `h3[@class='title']/a` |
| 作者 `<p class="author">` | `p.author` | `p[@class='author']` |
| 所有标签 `<ul class="tags"><li>` | `ul.tags li` | `ul[@class='tags']/li` |
| 取**文字** | 语法里没有，要靠框架方法（浏览器 `textContent`） | `.../text()` |
| 取 **href 属性** | 靠方法（WebMagic `.css("a","href")` / `.links()`；浏览器 `getAttribute`） | `.../@href` |

### 三条关键差异

1. **CSS 只负责"定位到元素"；XPath 能一路写到"元素里的文本/属性"**（`/text()`、`/@href`）。这就是 demo 抠字段那几行用 XPath 显得整齐的原因。
2. **`.get()` / `.all()` / `.replace()` / `.nodes()` / `.links()` 不是 XPath 专属**，它们是 WebMagic 的"结果处理"方法，换 CSS 照样能用——别被这点绕住。
3. **方言不完全通用**：WebMagic 底层是 jsoup/Xsoup，支持 `:contains(...)` 之类浏览器 CSS 不认的扩展伪类；反过来标准语法（class/id/属性选择器、`>`、空格）两边通用。

### 怎么选（直接给结论）

| 场景 | 用哪个 |
|---|---|
| 只按 class / id / 标签定位 | **CSS**（短、好读） |
| DevTools 调试、前端、Playwright | **CSS**（浏览器原生，`$$()` 一行搞定） |
| 按**文字内容**找元素（"找写着'下一页'的 a"）、找**父节点/兄弟**、取**第 N 个** | **XPath**（CSS 没这能力，只能靠代码再过滤） |
| **读公司项目代码** | **必须会看 XPath**——老 WebMagic/JsoupXpath 栈以它为主，仓库里还有 `JDXpathUtil`、`PDDXpathUtil` 这类工具 |
| 写新作业 | 跟着项目既有风格走，混用没问题 |

对你来说答案是：**CSS 用来"上手 + 调试"，XPath 用来"读懂公司代码"**。会了一个，另一个只是翻译，不用学两遍。

### 最小语法清单（各 5 个符号，10 分钟够）

CSS：
```
div          标签名
.book-card   class（点开头）
#app         id（# 开头）
空格         后代（任意层）：div.book-card a
>           直接子元素：ul.tags > li
```

XPath：
```
//           从任意深度找：//div
/            下一层：h3/a
标签名       直接写：p
[@class='x'] 按属性过滤：p[@class='author']
/text()      取文字      @href 取属性
```

### DevTools 验证法（写选择器前先在这里试，别改 Java 再重跑）

用浏览器打开 `pages/books-list.html` → F12 → **Console**：

```js
$$("div.book-card").length
// → 3，和 Java 里 cards 的数量一样

$$("div.book-card h3.title a").map(a => a.textContent)
// → ["Java 网络爬虫入门", "HTTP 权威指南", "CSS 选择器实战"]

$$("div.book-card ul.tags li").map(li => li.textContent)
// → 对应 BookListPageProcessor 第 68 行的 tags
```

- `$$("...")` = `document.querySelectorAll(...)`，但返回**真数组**，可直接 `.map()` / `.filter()`；`$("...")` 只返回第一个元素。
- 这两个快捷函数**只在 DevTools Console 有效**；若页面引入了 jQuery，`$` 可能被覆盖，`$$` 一般不受影响。
- ⚠️ **DevTools 看到的是 JS 渲染后的 DOM，而 WebMagic 的 `page.getHtml()` 是下载到的原始 HTML**。异步加载出来的内容在 DevTools 里能选中、在 `getHtml()` 里却选不中——这正是第 3 课要用 Selenium 的原因。在爬虫代码里对渲染后页面做同样的事，写 `driver.findElements(By.cssSelector("div.book-card"))`。

## 6. 开发者工具 F12（你的"透视镜"）

> Console 里用 `$$()` 快速验证选择器的写法，见上一节「DevTools 验证法」。

打开任意网页，按 **F12**：

- **Elements（元素）面板**：看到网页的真实结构（盒子套盒子）。右键页面元素 → "检查"，就能看到它被哪些 class 包裹——这就是你写选择器的依据。
- **Network（网络）面板**：点开 → 刷新页面 → 看浏览器发了哪些请求。
  - 找 **Fetch/XHR** 分类：很多动态页的数据其实是一个 JSON 接口，**直接请求这个接口**比用 Selenium 快一百倍（呼应辨析文档第 5 条）。
  - 点某个请求 → Preview/Response 看返回内容。
- **复制选择器**：在 Elements 里右键元素 → Copy → Copy selector / Copy XPath。可以拿来当起点，但**复制出来的往往是"绝对路径"（如 `html>body>div>div>div>...`），结构一变就失效**，要学会自己改写成按 class 的稳定写法。
