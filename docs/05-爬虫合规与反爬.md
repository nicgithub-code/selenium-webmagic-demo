# 五、爬虫合规与反爬（红线 + 正确姿势）

> 这一节不是"技术技巧"，是**底线**。新手最容易踩法律坑，请务必读完。

---

## 1. 法律红线（务必遵守）

| 行为 | 风险 |
|---|---|
| 爬取**个人信息**（姓名、电话、身份证、住址、账号）并收集/传播 | 违反《个人信息保护法》，情节严重可追刑责 |
| 绕过**登录鉴权 / 验证码**抓取需授权内容 | 可能构成"非法获取计算机信息系统数据"（《刑法》285 条） |
| 大规模抓取导致对方**服务器瘫痪**（DDoS 式高频请求） | 违反《刑法》286 条（破坏计算机信息系统） |
| 抓取后**商业化转售 / 不正当竞争** | 违反《反不正当竞争法》 |
| 无视 `robots.txt` 与网站声明，抓取明确禁止的内容 | 民事侵权、被起诉风险 |

### 安全的爬虫三原则
1. **只抓公开、非登录、非隐私的数据**；
2. **仅用于学习 / 个人分析，不二次分发、不商业化**；
3. **尊重对方：看 robots.txt、控制频率、留联系方式**。

---

## 2. robots.txt 是什么

网站根目录下的 `https://目标站/robots.txt` 是站长写的" crawl 规则"，例如：
```
User-agent: *
Disallow: /admin/
Disallow: /api/private/
```
意思是：所有爬虫不要抓 `/admin/` 和 `/api/private/`。**正式项目请先读它**，被 `Disallow` 的路径就别碰。

> 本工程练习站 `quotes.toscrape.com` 的 robots.txt 明确允许爬取，是专为练习设计的。

---

## 3. 礼貌抓取（既是道德也是自保）

- **加延时**：`Site.setSleepTime(500~1000)`，别像 DOS 攻击一样狂轰
- **设超时与重试**：`setTimeOut`、`setRetryTimes`，失败别死循环
- **控制并发**：WebMagic `thread(3~10)` 足够，不是越大越好
- **设 User-Agent**：伪装成正常浏览器（本工程已设）
- **提供联系方式**：大规模抓取可在 UA 里留邮箱，方便站长联系你

## 4. "反爬"到底是什么，以及正确思路

先纠正一个误区：**反爬 ≠ 你要去"破解"它**。合法合规的前提下，应对反爬的正确顺序是：

1. **优先找 JSON 接口（最重要）**
   很多"看起来动态"的页面，数据其实来自一个 XHR 接口。按 F12 → Network → Fetch/XHR，找到那个返回 JSON 的请求，**直接请求接口**。这比 Selenium 快 10~100 倍，且更稳。
2. **降低请求特征**
   随机延时、轮换 User-Agent、带上合理的 `Referer`/`Cookie`，模拟真人节奏。
3. **必要时用无头浏览器**
   当必须 JS 渲染 / 交互时，才上 Selenium / Playwright（本工程第 2、3 课）。
4. **别碰"硬破解"**
   验证码、登录鉴权、参数加密签名——这些一旦去"破解/逆向"，就游走在违法边缘，**不建议新手碰**。

> ⚠️ 关于"Selenium 能不能绕过反爬"：恰恰相反，无头浏览器特征更明显
> （`navigator.webdriver=true`、缺少浏览器插件、Canvas/WebGL 指纹异常等），
> 专业的反爬系统反而更容易认出它是机器人。所以它不是"隐身衣"，只是"能渲染 JS 的工具"。

---

## 5. 数据落地也要合规

- CSV/数据库里如果混入了个人信息，**立刻剔除**，不要长期留存。
- 对外提供数据前，确认版权与授权。
- 公司业务场景（如你项目里的"玺乐音乐"小程序）涉及用户信息时，一律走**官方授权接口**，不要爬虫替代。

---

## 一句话总结

> **能不爬就不爬，能找接口就别用浏览器，能公开就别碰隐私，能慢就别快。**
> 把爬虫当作"在对方允许范围内、礼貌地自动获取数据"的工具，而不是"突破限制"的武器。
